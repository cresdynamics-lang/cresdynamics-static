How We Work

The standards we hold ourselves to.

These are not aspirations, they are the minimum bar for everyone on the team.

Ship weekly, demo weekly

We show working software every week. No "almost done" updates. If it's not demoable, it's not done.

Own the problem, not the task

We don't assign tickets. We assign problems. You figure out the best solution and build it.

Write it down or it didn't happen

Architecture decisions, API contracts, process changes, everything gets documented. Context is a team asset.

Honest over comfortable

We tell clients when something won't work. We tell each other when the code isn't good enough. Kindness and honesty are the same thing.
